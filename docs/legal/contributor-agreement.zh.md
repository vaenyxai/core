## 1. 本协议何时适用

1.1 **仅在发布时适用。** 本协议**在您发布之时**适用——即您将 Method、Routine、示例(Example)或其他内容发布至公共的 Vaenyx 社区 Library(“**Library**”——在产品中显示为 “Community”,而您设备上的私人存储区显示为 “Library”)之时。完成发布步骤,即表示您就该项贡献内容接受本协议。

1.2 **本地与私人创建不在本协议范围内。** 在您自己的设备上**私下创建、编辑或使用 Method 和 Routine 无需任何协议**,亦不依本协议授予我们任何权利。您创建的一切默认存入您的私人库;除非您明确发布,否则您创建的任何内容都不会依本协议被发布。另外——即使您从未发布任何内容、也从未接受本协议——在您已作出肯定性的社区共享选择的情形下(这是一项在安装引导中与《服务条款》的接受一并呈示、但相互独立的明确选择,不预选任何选项,并可随时在设置中更改;在您实际作出该选择之前,不会共享任何内容,共享功能亦不会在任何安装实例上运行——包括升级之后),来自您私人使用的去标识化改进模式可能被公开共享,并依《服务条款》第 7.4 条获得许可(见第 9 条)。

1.3 **使用 Library 不在本协议范围内。** 下载和使用社区内容无需账户,受《服务条款》而非本协议约束。

1.4 **每次发布均为一次独立的接受。** 本协议(以届时有效的版本为准)分别适用于您发布的每一项贡献内容,包括其每个新版本。

1.5 **发布期范围(截至生效日期)。** 本版本不提供社区分享上传、Example 附带、去标识化或预览,也不提供 Merit。当前的分享设置仅为一项本机偏好,不授权任何上传,也不构成任何许可或精神权利同意。此后新增的能力,在被标记为启用、具备保障、作出告知并经单独选择之前,始终保持关闭。因此,本协议中描述 Example、分享上传或 Merit 的条款目前没有适用对象,仅在明细表将相应能力标记为启用时才生效。

## 2. 定义

- “**Method**”——发布至 Library 的原子化、声明式构建单元。
- “**Routine**”——由若干 Method 加声明式编排组成的、面向用户的成品。
- “**示例(Example)**”——随 Method 或 Routine 一同发布、或向其贡献的、经去标识化的输入/输出或纠正模式。
- “**贡献内容(Contribution)**”——您发布至 Library 的任何 Method、Routine、示例、描述、元数据或其他内容,包括其每个版本。
- “**声明式内容**”——描述*做什么*的配方、指令、schema 与配置;而非可运行的外来程序代码。仅含声明式内容是 Library 的一项核心安全特性。
- “**Merit**”——在您所用的 Vaenyx 版本提供的情况下,指第 8 条所述的非金钱性创作者声誉记录。截至生效日期,Merit 未提供。
- “**发布服务(Publish Service)**”——由运营方托管的中央发布服务,所有发布均须经由它进行。您的安装把贡献内容的声明式文件与您已登录的身份发送到发布服务;唯有发布服务持有写入公开仓库的凭据。您自己从不向公开仓库写入,也从不持有其写入凭据。
- “**Library 基础设施**”——用于存储和分发 Library 的系统:发布服务、发布服务代表您向其提交内容的公开仓库,以及各安装读取的目录与索引。适用于您所用版本的服务商、认证选项、基础设施与端点,载于当前明细表、适用的逐点告知与《第三方声明》文件。那些是事实性告知:它们不并入本协议;对它们的更新不修改本协议,除非该变更改变了某项合同权利、义务或风险分配。

## 3. 谁可以发布(身份)

3.1 **须经验证登录。** 发布须通过您所用版本提供的某个登录服务商完成经验证的登录;当前可用的选项载于明细表并在登录步骤中标明。使用 Library 不需要账户,发布则需要。任何登录选项相较其他选项均不带来优势,也没有任何选项要求您拥有公开仓库托管方的账户。您的公开署名是您自行设定的显示名称:首次发布流程要求您明确选择,并预填一个生成的化名 —— **绝不会预填您登录账户上的姓名** —— 因此只有当您自己填入真名时,真名才会成为您的署名;此后每次发布均可随时修改(见明细表条目 `flow.publication.signin` 与 `flow.publication.submission`)。**您的署名是公开的,且在我们触及不到的副本中是永久的** —— fork、镜像与已安装副本(第 8.1–8.2 与 10.4 条);我们自有仓库的历史,仅在第 10.4(c) 条的例外情形下才可更正。若您发布时的显示名称就是真名,您的真名将被公开、写入公开的 git 历史,并随 CC BY 4.0 署名在全球流转 —— 首次发布前请检查您的显示名称。保持私密的是您经验证的登录身份 —— 服务商、账户标识符与邮箱;我们仅存储署名、已发布内容管理、去重、执法与 Merit 所需的最少账户信息。

3.2 **年龄。** Vaenyx 是面向 18 岁及以上人群的一般受众产品。您必须年满 18 周岁并具有订立有约束力协议的行为能力,方可发布。

3.3 **不得冒充。** 您不得以冒充他人、其他创作者、组织或品牌、或容易与之混淆的名称或身份发布。由于发布服务在提交时以您账户的显示名称加盖署名(第 8.1 条),您的安装实例无法附加与账户显示名称不同的署名——但该盖印并不核实您的显示名称是否为您的真实姓名,亦不核实其是否唯一。对违反本第 3.3 条的显示名称,我们可予以屏蔽、重置或要求更改,并可将第 3.4 条的近似名称筛查同样适用于显示名称与贡献内容名称。

3.4 **名称。** 贡献内容的名称在提交时即被保留。对与现有内容近似、恶意抢注、违反《商标政策》滥用 Vaenyx 名称或 logo、或具有误导性的名称,我们可予以屏蔽、拒绝或重新分配。已移除贡献内容的名称不会释放给其他账户重复使用;发布该贡献内容的账户可以重复使用其名称,但移除系出于安全或法律原因或恶意行为的除外。保留名称并不使您就该名称获得超出您贡献内容目录条目之外的商标权或其他专有权利。

3.5 **受信任状态。** 任何“受信任创作者”(trusted creator)或类似状态均设有时间门槛、由我们酌情授予,并在关联身份发生变化时自动撤销。它是一项 Library 完整性信号,不是资质、背书或权利。

## 4. 可以发布什么(内容标准)

4.1 **仅限声明式内容。** 贡献内容必须是声明式内容。您不得发布可运行的外来程序代码,也不得规避、伪装或夹带内容绕过“仅限声明式”约束(例如把可执行载荷编码进指令或 schema 中)。发布服务会在提交入库前校验每次提交(仅声明式、路径安全、大小上限),但其自动检查并不免除您的这项义务。

4.2 **不得含恶意或有害内容。** 您不得发布违法、恶意、欺骗性或有害的内容,不得发布给出不安全指引的内容,也不得发布旨在破坏任何系统或数据、从中窃取数据、或对其实施未经授权控制的内容。

4.3 **不得含个人信息。** 贡献内容(包括示例)不得包含任何可识别个人的个人信息,但第 8 条所述与您本人相关的署名信息除外。示例在发布前必须**去标识化**。发布流程中的去标识化关卡旨在协助对示例去标识化,但不保证捕捉一切,您仍须对所发布的内容负责:请自行审查您的贡献内容,不要发布真实姓名、联系方式、财务细节、健康信息或任何其他可识别个人的信息。

4.4 **不构成专业意见。** 贡献内容是一般性的工具与信息,不是医疗、法律、财务、税务或其他专业意见,也不得以专业意见的形式呈现。

4.5 **标准适用于每个版本。** 您发布的每个新版本都必须独立满足上述标准。正常运行中 Method 以不可变方式进行版本管理,Routine 则固定(pin)所用 Method 的版本;有缺陷的版本不会被悄悄修改,只会被新版本取代(关于移除的限度见第 10 条,以及第 10.4 条所述可清除历史的例外情形)。
